================================================================================
STANDARD OPERATING PROCEDURE (SOP): ADDING NEW FEATURES TO ENTITIES
================================================================================
Project: Cafeteria Ordering Backend (Spring Boot + MySQL/XAMPP)
Author: AI Developer Collaborator
================================================================================

This document outlines the step-by-step workflow required to add a new
feature (such as fetching, creating, updating, or deleting data) for any
existing entity in the system.

By following this strict, bottom-up flow (Database -> Repository -> Service ->
Controller), you ensure compilation safety and clean architecture.

---
PHASE 1: THE DATABASE LAYER (MySQL / phpMyAdmin)
---
Before touching any Java code, make sure your database is prepared.

1. Open phpMyAdmin (http://localhost/phpmyadmin)[cite: 1].
2. If your new feature requires a new database column, a new table, or a
   changed constraint, execute the corresponding SQL query first[cite: 1].
3. Ensure you have dummy testing records in place so you can verify the results
   immediately once the code is compiled.

---
PHASE 2: THE ENTITY & REPOSITORY LAYER
---
Update the Java classes that directly speak to the database.

1. Locate your target entity class inside the 'entity' package (e.g., User.java)[cite: 1].
   - If you added columns, declare them as private variables with appropriate
     Lombok annotations (@Getter, @Setter)[cite: 1].
   - Ensure the JPA annotations (@Column, @ManyToOne, etc.) exactly match
     your database columns[cite: 1].

2. Locate your repository interface inside the 'repository' package (e.g., UserRepository.java)[cite: 1].
   - Standard CRUD operations (findById, findAll, save, deleteById) are already
     provided by JpaRepository out-of-the-box.
   - If your feature requires custom filtering (e.g., "find items by price"),
     declare a custom query method here.
     Example: List<MenuItems> findByPriceLessThan(BigDecimal maxPrice);

---
PHASE 3: THE SERVICE LAYER (The Business Logic)
---
This is a two-step process: you must declare the feature in the contract
(interface) before writing the actual code (implementation)[cite: 1].

1. Step A: Update the Service Interface
   - Locate the target interface in 'service/interfaces/' (e.g., UserService.java)[cite: 1].
   - Declare the method signature.
     Example: User getUserById(Long id);[cite: 1]

2. Step B: Update the Service Implementation
   - Locate the target class in 'service/implementation/' (e.g., UserServiceImpl.java)[cite: 1].
   - Spring/IntelliJ will highlight the class in red because it is missing the new
     method[cite: 1].
   - Implement the business logic using the autowired Repository[cite: 1].
     Example:
     @Override
     public User getUserById(Long id) {
         return userRepository.findById(id)
                 .orElseThrow(() -> new RuntimeException("User not found with ID: " + id));
     }

---
PHASE 4: THE CONTROLLER LAYER (The HTTP API)
---
Expose your new business logic to the outside world (browser, Postman, mobile app).

1. Locate the matching controller in the 'controller' package (e.g., UserController.java)[cite: 1].
2. Create a public method and bind it to an HTTP verb annotation:
   - For retrieving data: @GetMapping("/your-route")[cite: 1]
   - For saving new data: @PostMapping("/your-route")[cite: 1]
   - For updating data: @PutMapping("/your-route")
   - For deleting data: @DeleteMapping("/your-route")
3. Call the service method you created in Phase 3 and wrap the result in a ResponseEntity[cite: 1].
   Example:
   @GetMapping("/{id}")
   public ResponseEntity<User> getUserById(@PathVariable Long id) {
       return ResponseEntity.ok(userService.getUserById(id));[cite: 1]
   }

---
PHASE 5: TESTING & VALIDATION
---
Verify that your endpoint is working correctly on localhost.

1. Restart your Spring Boot application in IntelliJ[cite: 1].
2. For @GetMapping requests, test directly in your browser[cite: 1].
3. For @PostMapping/@PutMapping/@DeleteMapping requests, construct a Curl command
   (or use a client like Postman) to send JSON payloads[cite: 1].
4. Look for the following common issues:
   - 404 Not Found: Check the path spelling in your Controller[cite: 1].
   - 500 StackOverflowError: Check if two connected entities (like User and Role)
     are serializing each other back-and-forth endlessly[cite: 1]. If so, add
     @JsonIgnore or @JsonBackReference to one side of the relationship[cite: 1].
