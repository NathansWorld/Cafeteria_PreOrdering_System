1. AUTHENTICATION & SESSION MANAGEMENT (JWT & BLACKLIST)
------------------------------------------------------------------------

[A] REGISTER A NEW USER (POST)
- Note: Registers a user, hashes password via BCrypt, assigns default role, and returns JWT token.
- Curl Command (Git Bash, macOS, Linux):
curl -X POST http://localhost:8080/api/auth/register \
     -H "Content-Type: application/json" \
     -d "{\"firstName\":\"Charlie\",\"lastName\":\"Brown\",\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"

- Curl Command (Windows CMD):
curl -X POST http://localhost:8080/api/auth/register -H "Content-Type: application/json" -d "{\"firstName\":\"Charlie\",\"lastName\":\"Brown\",\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"

- Curl Command (Windows PowerShell):
curl.exe --% -X POST "http://localhost:8080/api/auth/register" -H "Content-Type: application/json" -d "{\"firstName\":\"Charlie\",\"lastName\":\"Brown\",\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"


[B] LOGIN / GENERATE JWT TOKEN (POST)
- Note: Validates credentials and returns a Bearer JWT token valid for stateless requests.
- Curl Command (Git Bash, macOS, Linux):
curl -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d "{\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"

- Curl Command (Windows CMD):
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"

- Curl Command (Windows PowerShell):
curl.exe --% -X POST "http://localhost:8080/api/auth/login" -H "Content-Type: application/json" -d "{\"email\":\"charlie@campus.edu\",\"password\":\"securepassword123\"}"


[C] GET CURRENT AUTHENTICATED USER PROFILE (GET)
- Note: Pass the Bearer JWT token obtained from login. Expects HTTP 200 OK with UserProfileDTO.
- Curl Command (Git Bash, macOS, Linux):
curl -i -X GET http://localhost:8080/api/auth/me \
     -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE"

- Curl Command (Windows CMD / PowerShell):
curl.exe -i -X GET http://localhost:8080/api/auth/me -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE"


[D] LOGOUT / INVALIDATE JWT TOKEN (POST)
- Note: Adds token to TokenBlacklistService to block subsequent usage immediately.
- Curl Command (Git Bash, macOS, Linux):
curl -i -X POST http://localhost:8080/api/auth/logout \
     -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE"

- Curl Command (Windows CMD / PowerShell):
curl.exe -i -X POST http://localhost:8080/api/auth/logout -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE"


[E] VERIFY BLACKLIST / RE-ATTEMPT PROFILE ACCESS (EXPECTS 401 UNAUTHORIZED)
- Note: Re-running GET /api/auth/me with the logged-out token must be rejected by JwtAuthenticationFilter.
- Curl Command (Git Bash, macOS, Linux):
curl -i -X GET http://localhost:8080/api/auth/me \
     -H "Authorization: Bearer YOUR_LOGGED_OUT_TOKEN_HERE"

- Curl Command (Windows CMD / PowerShell):
curl.exe -i -X GET http://localhost:8080/api/auth/me -H "Authorization: Bearer YOUR_LOGGED_OUT_TOKEN_HERE"

8. ORDER LIFECYCLE & STATUS CHANGES
------------------------------------------------------------------------

[A] UPDATE ORDER STATUS (PUT)
- Note: Updates the status of a specific order (e.g., Order ID 1) to a valid database status (e.g., "Submitted", "Accepted", "Preparing", "Ready", "Collected", "Cancelled").
- Important: This action also automatically logs a transition history audit entry into your database's `order_status_history` table.

- Curl Command (Git Bash, WSL, Linux, or macOS):
curl -X PUT http://localhost:8080/api/orders/1/status \
     -H "Content-Type: application/json" \
     -d '{"statusName": "Preparing"}'

- Curl Command (Windows PowerShell):
curl.exe --% -X PUT "http://localhost:8080/api/orders/1/status" -H "Content-Type: application/json" -d "{\"statusName\":\"Preparing\"}"

[B] CANCEL ORDER (POST/PUT)
- Note: Cancels a specific order (e.g., Order ID 1). Highly restricted.
- Safety Rules: Will only succeed if the order's current status is "Submitted" or "Accepted". If the order is already "Preparing", "Ready for Collection", or "Completed", the API will reject this cancellation request with a 400 Bad Request.

- Curl Command (Git Bash, WSL, Linux, or macOS):
curl -X POST http://localhost:8080/api/orders/1/cancel

- Curl Command (Windows PowerShell):
curl.exe --% -X POST "http://localhost:8080/api/orders/1/cancel"
